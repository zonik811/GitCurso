Estos comandos cubren el 80% de tu uso diario de Git. Domínalos y ya podrás trabajar.

## El mapa de comandos

Antes de entrar en detalle, esta es la chuleta completa de la lección:

| Comando | Para qué sirve |
| --- | --- |
| `git init` | Convierte la carpeta actual en un repositorio Git |
| `git status` | Muestra qué ha cambiado y qué está preparado |
| `git add` | Pasa cambios al **staging** (los deja listos) |
| `git commit` | Guarda una foto del staging en el historial |
| `git log` | Muestra el historial de commits |
| `git diff` | Muestra las diferencias línea por línea |
| `git rm` | Borra un archivo y prepara la eliminación |
| `git mv` | Renombra un archivo y prepara el cambio |
| `git show` | Inspecciona un commit concreto |

## `git init` — crear un repositorio

Convierte una carpeta normal en un repositorio Git:

```bash
mkdir mi-proyecto
cd mi-proyecto
git init
```

```text
Initialized empty Git repository in /ruta/mi-proyecto/.git/
```

A partir de ahora Git observa esa carpeta. Para crear el repo y la carpeta a la vez:

```bash
git init mi-proyecto
```

Git solo crea una carpeta oculta `.git/` con toda la información. Si la borras, el proyecto deja de ser un repositorio (pero tus archivos siguen ahí). Volver a ejecutar `git init` sobre un repo existente **no lo borra**: solo lo reinicializa.

## `git status` — el estado actual

Tu comando más usado. Muestra qué cambió, qué está preparado y qué está sin rastrear:

```bash
git status
git status -s     # versión corta
```

```text
 M estilos.css      # modificado, sin preparar
A  index.html       # añadido (staged)
?? notas.txt        # sin rastrear
```

En la versión corta hay **dos columnas** antes del nombre: la primera es lo preparado (staging) y la segunda lo que aún está sin preparar.

| Código | Significado |
| --- | --- |
| `??` | Archivo sin rastrear (Git aún no lo conoce) |
| `A ` | Añadido y preparado |
| ` M` | Modificado, pero sin preparar |
| `M ` | Modificado y preparado |
| `MM` | Preparado y vuelto a modificar después |
| `D ` | Borrado y preparado |

## `git add` — preparar cambios

Mueve cambios del working directory al staging:

| Forma | Qué hace |
| --- | --- |
| `git add archivo.txt` | Prepara un archivo |
| `git add carpeta/` | Prepara toda una carpeta |
| `git add .` | Todo lo nuevo y modificado desde el directorio actual |
| `git add -A` | Todo el repositorio, **incluidos los borrados** |
| `git add -u` | Solo archivos ya rastreados (ni nuevos) |
| `git add "*.css"` | Por patrón |
| `git add -p archivo.txt` | Por trozos (modo interactivo) |

<Callout type="info">
  `git add .` y `git add -A` se parecen, pero no son iguales: `.` afecta solo a la carpeta donde estás, mientras que `-A` recorre todo el repositorio. En la raíz del proyecto hacen lo mismo.
</Callout>

Preparar **solo partes** de un archivo (muy útil cuando has mezclado dos cambios):

```bash
git add -p archivo.txt
```

## `git commit` — guardar una foto

Registra lo que está en el staging en el historial:

```bash
git commit -m "Añade formulario de contacto"
```

Sin `-m`, Git abre tu editor para que escribas un mensaje largo.

```bash
git commit                 # abre el editor
git commit -am "mensaje"   # add + commit de archivos ya rastreados (¡no incluye nuevos!)
```

### Buenos mensajes de commit

Un buen mensaje explica el **qué** y el **por qué**:

```text
✅ Corrige el cálculo del total cuando hay descuento

El IVA se aplicaba antes del descuento, lo que inflaba el precio.
Ahora se calcula sobre el subtotal ya descontado.
```

Evita:

```text
❌ cambios
❌ arreglado
❌ asdf
```

## `git log` — ver el historial

```bash
git log                    # historial completo
git log --oneline          # una línea por commit
git log --oneline --graph  # con gráfico de ramas
git log -5                 # los últimos 5
git log --stat             # con el resumen de archivos tocados
git log -p                 # con las diferencias de cada commit
git log --author="Ana"     # filtrar por autor
git log --since="2 weeks ago"
```

```text
a1b2c3d (HEAD -> main) Añade formulario de contacto
9f8e7d6 Corrige el cálculo del total
4c3b2a1 Primer commit
```

Cada commit tiene un **hash** (ej. `a1b2c3d`), su identificador único. Puedes referirte a él por sus primeros caracteres.

## `git diff` — ver qué cambió

Muestra las diferencias línea por línea:

```bash
git diff                   # cambios sin preparar
git diff --staged          # cambios preparados (staged)
git diff HEAD              # todos los cambios desde el último commit
git diff --stat            # resumen: solo archivos y líneas
git diff main feature      # diferencias entre dos ramas
```

```diff
- const total = precio * 1.21;
+ const total = precio * 1.21 * (1 - descuento);
```

<Callout type="tip">
  Regla de oro: `git diff` (sin más) compara **working directory contra staging**, no contra el último commit. Para ver todo lo que cambiará tu próximo commit usa `git diff HEAD`.
</Callout>

## Practica los comandos

Usa esta **terminal interactiva** para ejecutar de verdad `git init`, `git status`, `git add`, `git commit`, `git log`, `git diff`, `git rm`, `git mv` y `git show`. Crea archivos con `echo "texto" > archivo` y observa el panel derecho.

<GitTerminal title="Practica: comandos esenciales" advanced />

<Callout type="tip">
  Prueba esta secuencia y observa cómo cambian los tres paneles: <code>git init</code> → <code>echo "Hola" &gt; nota.txt</code> → <code>git status -s</code> → <code>git add .</code> → <code>git status</code> → <code>git commit -m "Primer commit"</code> → <code>git log --stat</code>. Después prueba <code>git mv nota.txt apuntes.txt</code> y mira cómo <code>git status</code> detecta el renombrado.

## `git rm` y `git mv` — borrar y renombrar

```bash
git rm archivo.txt             # borra del disco y lo prepara
git rm --cached archivo.txt    # deja de rastrearlo, sin borrar el archivo
git mv viejo.txt nuevo.txt     # renombra y prepara el cambio
```

- `git rm` es como borrar el archivo y hacer `git add` de la baja, todo en un paso.
- `git rm --cached` es clave cuando subiste por error un archivo que ahora quieres ignorar: desaparece del repositorio pero se queda en tu disco.
- `git mv` equivale a renombrar y preparar el cambio. Git detecta que el contenido es el mismo y lo muestra como `renamed:`.

## `git show` — inspeccionar un commit

```bash
git show a1b2c3d
git show HEAD              # el último commit
git show HEAD~1            # el anterior
```

Muestra el autor, la fecha, el mensaje y los cambios de ese commit. Es `git log -p` para un solo commit.

## Errores comunes

| Mensaje | Qué significa | Cómo salir |
| --- | --- | --- |
| `fatal: not a git repository` | La carpeta no es un repo | Ejecuta `git init` |
| `nothing to commit, working tree clean` | No hay cambios, o ya commiteaste | Revisa con `git status` |
| `no changes added to commit` | Hay cambios pero no los preparaste | `git add .` y vuelve a commitear |
| `pathspec 'x' did not match any files` | El nombre no existe o está mal escrito | Compruébalo con `ls` o `git status` |
| `Aborting commit due to empty commit message` | Olvidaste el `-m` | `git commit -m "mensaje"` |
| `Please tell me who you are` | Faltan tu nombre y correo | Configúralos con `git config` |

## Flujo completo de ejemplo

```bash
mkdir blog && cd blog
git init
git config user.name "Tu Nombre"
git config user.email "tu@email.com"

echo "# Mi Blog" > README.md
git status
git add README.md
git commit -m "Crea el README inicial"

echo "body { margin: 0; }" > estilos.css
git add estilos.css
git commit -m "Añade estilos base"

git log --oneline
```

```text
d4e5f6a Añade estilos base
b2c3d4e Crea el README inicial
```

<Callout type="tip">
  Commitear seguido y en unidades pequeñas es mejor que un commit gigante al final del día. Cada commit debería ser un cambio coherente que puedas describir en una frase.
</Callout>
