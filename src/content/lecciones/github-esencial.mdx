GitHub es donde tu código vive online y donde ocurre la colaboración. Vamos a configurar todo correctamente desde el principio.

## Crear tu cuenta

1. Entra a [github.com](https://github.com) y pulsa **Sign up**.
2. Elige un **nombre de usuario** profesional (será parte de tu identidad como desarrollador: aparecerá en la URL de tus repos).
3. Verifica tu correo.
4. Activa la **autenticación en dos pasos (2FA)**: GitHub la exige cada vez más y protege tu cuenta.

<Callout type="tip">
  Tu perfil de GitHub es tu portafolio. Elige un buen avatar, escribe una bio clara y fija (*pin*) tus mejores repositorios.
</Callout>

## Crear un repositorio

Desde el botón **New repository**:

- **Repository name**: en minúsculas y con guiones, ej. `mi-primer-proyecto`.
- **Description**: una frase de qué hace.
- **Public / Private**: público para portafolio, privado para trabajo sensible.
- **Add a README**: márcalo, así el repo nace con documentación.
- **Add .gitignore**: elige la plantilla de tu lenguaje.
- **Choose a license**: si es código abierto, añade una licencia.

## Anatomía de un repositorio

| Elemento | Para qué sirve |
| --- | --- |
| **README.md** | La portada del proyecto. Lo primero que ve quien llega. |
| **LICENSE** | Los términos legales de uso. |
| **.gitignore** | Qué archivos no versionar. |
| **Issues** | Reportar bugs y proponer mejoras. |
| **Pull Requests** | Proponer cambios para revisión. |
| **Actions** | Automatización (tests, despliegues) en la nube. |
| **Wiki** | Documentación extensa. |
| **Releases** | Versiones etiquetadas con notas. |

## Un buen README

Un README mínimo debería responder: ¿qué es esto?, ¿cómo se instala?, ¿cómo se usa?

```markdown
# Mi Proyecto

Una breve descripción de qué hace y para quién.

## Demo

Enlace a una demo en vivo o capturas de pantalla.

## Instalación

    npm install

## Uso

    npm start

## Tecnologías

- JavaScript
- Node.js

## Licencia

MIT
```

GitHub renderiza Markdown, así que puedes usar títulos, listas, tablas, código y emojis.

## Conectar Git con GitHub: autenticación

Git necesita autenticarse para hacer `push`. Hay dos formas principales:

### Opción A — HTTPS con token (más fácil de empezar)

Desde 2021 GitHub **no acepta tu contraseña** por HTTPS. Necesitas un **Personal Access Token (PAT)**:

1. Ve a **Settings → Developer settings → Personal access tokens → Tokens (classic)**.
2. **Generate new token (classic)**.
3. Marca el scope `repo` (y `workflow` si usarás Actions).
4. Copia el token **ahora** (no se vuelve a mostrar).

Cuando Git te pida contraseña al hacer push, pega el token.

```bash
git clone https://github.com/usuario/mi-proyecto.git
# Username: tu-usuario
# Password: <pega aquí el token>
```

Para no escribirlo cada vez:

```bash
git config --global credential.helper store     # guarda en texto plano (cómodo, menos seguro)
git config --global credential.helper manager   # gestor de credenciales del sistema (recomendado)
```

### Opción B — SSH (más cómoda a largo plazo)

Generas un par de claves y registras la pública en GitHub. Después, no vuelves a escribir credenciales.

**1. Genera la clave:**

```bash
ssh-keygen -t ed25519 -C "tu@email.com"
```

Pulsa Enter para aceptar la ruta por defecto (`~/.ssh/id_ed25519`). Puedes poner una passphrase para más seguridad.

**2. Copia la clave pública:**

```bash
# macOS
pbcopy < ~/.ssh/id_ed25519.pub

# Windows (Git Bash)
clip < ~/.ssh/id_ed25519.pub

# Linux
cat ~/.ssh/id_ed25519.pub   # y copia manualmente
```

**3. Pégala en GitHub:** Settings → SSH and GPG keys → New SSH key.

**4. Prueba la conexión:**

```bash
ssh -T git@github.com
```

```text
Hi usuario! You've successfully authenticated...
```

**5. Usa URLs SSH al clonar:**

```bash
git clone git@github.com:usuario/mi-proyecto.git
```

| | HTTPS + Token | SSH |
| --- | --- | --- |
| Configuración | Fácil | Media |
| Credenciales | Token (caduca) | Clave (permanente) |
| Ideal para | Empezar, CI, scripts | Uso diario |

## Otros elementos útiles

- **Gists**: fragmentos de código compartibles.
- **Stars**: marcar repos que te gustan (y que otros te marquen).
- **Fork**: copiar el repo de otro a tu cuenta para proponer cambios.
- **GitHub Pages**: hosting gratuito para sitios estáticos.
- **GitHub CLI (`gh`)**: gestiona GitHub desde la terminal.

```bash
gh auth login
gh repo create mi-proyecto --public --clone
```
